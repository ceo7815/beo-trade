# ארכיטקטורה

מונוליט מודולרי ב-Python ועובד נפרד. הדשבורד הוא Next.js.

זרימת החלטה:

נתוני שוק → נרמול → סינון כמותי → אירועים וחדשות → בחירת חוזים → GPT-6 Sol על הרשימה הקצרה בלבד → שערי איכות → BUY או דיכוי.

אותה פונקציה `run_scan` רצה על נתונים חיים ועל שידור חוזר היסטורי. שידור חוזר מחזיר רק רשומות עם חותמת זמן קטנה או שווה לזמן ההחלטה.

המספרים — מחיר, יווניות, תרחישים, כמות וגודל פוזיציה — מחושבים בקוד. המודל בוחר חוזה מתוך הרשימה ומסביר. מחיר שהמודל מחזיר לא מוצג.

ספקים:

`MARKET_DATA_PROVIDER`, `OPTIONS_DATA_PROVIDER`, `NEWS_PROVIDER`.

כרגע הערך התקין היחיד להרצה חיה הוא `unconfigured`. מתאם של ספק אמיתי ייכנס תחת `backend/app/providers` בלי לשנות את המנוע.

תמונת ברוקר:

ה-API וה-worker הם שני תהליכים על אותו volume (`beo_data`). אין Redis. חשבון, פוזיציות, פקודות פתוחות ושעון נשמרים בקובץ `data/broker_snapshot.json` לכמה שניות (ברירת מחדל 5, וכל ערך מחוץ ל-5–10 נחתך). בתוך תהליך, קוראים מקבילים מחכים לבקשה אחת. בין תהליכים, נעילת קובץ מונעת שתי משיכות במקביל. זרם המסך קורא רק מהקובץ. בדיקת יציאה שצריכה פוזיציות מרעננת באותו נתיב אם התמונה הגיעה ל-TTL. `BROKER_SNAPSHOT_TTL_SECONDS` קובע את החלון.
